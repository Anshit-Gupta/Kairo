Kairo : 
persistent key-value store in go 


why build this ? why not just use a hashmap?
go's hashmap is pretty efficient too 

but using a plain map have some issues :

1.Data disappears when program stops 
-kairo : persistence 

2. Multiple goroutines can access the store 
- can be dealt with using locking ( sync.Mutex,sync.RWMutex)

3. A map does'nt provide a server or protocol 
kairo : a way for clients to communicate 

4. Handle failures and edge cases

# Pointer receivers 
A value receiver works with a copy of the struct. A pointer receiver works with a pointer to the original struct.

func (c *Counter) AddOne() {
    c.Value++
}

#Method with a receiver 
func ***(p Paragraph)*** summary() {
    fmt.Println(p.text)
}
